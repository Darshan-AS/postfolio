# Session Log: 2026-09-02 (Session 9)

## Objective
Tackle "The Core Mismatch: `_userId` / `AppUser` vs. `agentId` / `agent_profiles`" by decoupling Auth user representation from Agent domain representation, and renaming repository variables to match Ubiquitous Language.

## Findings & Decisions
- **Decoupled Auth Context from Business Domain**:
  - Auth model represents who logged in (Identity Context) and shouldn't be polluted with rich Agent features.
  - Refactored `AppUser` to `AuthUser` inside `lib/features/auth/domain/auth_user.dart`.
  - Left the `Agent` or `AgentProfile` naming space available for future rich business profiles under a separate `features/agent/` context.
- **Resolved Supabase Name Collision**:
  - `supabase_flutter` already exports a class named `AuthUser`.
  - Added `hide AuthUser` on the Supabase import inside `SupabaseAuthRepository` to resolve naming ambiguity cleanly.
- **Normalized Ubiquitous Language in Repositories**:
  - Replaced technical-centric names like `_userId` and `userId` inside the repositories with `_agentId` and `agentId` to align directly with the DB schema (`agent_profiles` table, `agent_id` columns) and domain terminology.
  - Applied renaming to Firestore and Supabase customer/deposit repositories.
