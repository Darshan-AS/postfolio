10. Monthly Operations KPI & Filter Harmonization Fix:
   - Diagnosed user-reported discrepancy where "To Collect" filter chip showed count (2) while only 1 account appeared in the list for August 2026.
   - Root cause: Account 3 had full installment principal paid and deposited to Post Office (`poStatus: paid`), but an unpaid ₹100 default penalty fee. `isSettled` checked `isFullySettled` (which required late fees zeroed), causing `isSettled` to evaluate to false and falling into an unhandled `else` in `monthlyOperationsKpi` which incremented `toCollectCount++`. In contrast, the list filter checked `item.isCustomerPending` (`!installment.isInstallmentPaid`), correctly excluding it from the list.
   - Fix applied:
     - Aligned `isSettled` to reflect monthly deposit cycle settlement: `installment.isInstallmentPaid && installment.poStatus == RDPoStatus.paid`. Unpaid default fees remain clearly indicated on the card subtitle.
     - Updated `monthlyOperationsKpi` loop to strictly match filter predicates with explicit `else if (item.isCustomerPending)`.
     - Added comprehensive unit tests in `test/rd_monthly_operations_test.dart` verifying settled behavior with unpaid late fees and state partitioning.
   - Verification: `dart analyze --fatal-infos` (0 issues), all 27 tests passing on Chrome (`flutter test --platform=chrome`).
