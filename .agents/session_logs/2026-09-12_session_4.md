## Root Cause Analysis
- The UI layer (`RDMonthlyOperationCard`, `RDMonthlyOperationsView`, `RDLogPaymentSheet`), domain methods (`totalOutstandingPayable`, `hasOverdueDebt`), and KPI calculations had all been completed in Session 3 and tested with explicit domain unit tests.
- However, in `rd_monthly_operations_controller.dart`, `rawMonthlyOperationsStream` was instantiating `RDMonthlyOperationItem` without passing `priorOverdueCount` or `priorOverdueAmount`, causing them to default to `0` and `0.0`.
- Furthermore, `watchInstallmentsForMonth` only queried installments with `installment_date` within the selected month, meaning the client never received context on whether prior months had unpaid installments.
- As a result, when looking at September 2026, the application had no knowledge that August 2026 was overdue, so neither the top banner, card badges, red indicators, nor "Pay All" buttons rendered.

## Bug Fix: "Log payment" Debug Mode Freeze / Unhandled Exception
- **Symptom**: Clicking "Log payment" in the Monthly Operations Hub threw an unhandled exception and paused the Dart debugger ("freeze" in debug mode).
- **Root Cause**:
  - In `RDMonthlyOperationsView`, `onLogPayment` was calling `await ref.read(rdInstallmentsStreamProvider(item.deposit.id).future)`.
  - `rdInstallmentsStreamProvider` is an `AutoDisposeStreamProvider`. Because `RDMonthlyOperationsView` did not watch this provider, calling `ref.read` without an active subscriber caused Riverpod's scheduler to dispose the provider in the next microtask while it was still in the loading state.
  - This triggered Riverpod's internal assertion: `Bad state: The provider rdInstallmentsStreamProvider(...) was disposed during loading state, yet no value could be emitted.`
  - In debug mode, the Dart debugger broke on this unhandled `StateError`, pausing execution and freezing the app UI.
- **Solution**:
  - Added direct, clean one-shot fetch method `Future<Result<List<RDInstallment>, String>> getRDInstallments(String rdId)` to `RecurringDepositRepository` and implemented across `SupabaseRecurringDepositRepository`, `FakeRecurringDepositRepository`, and `FirestoreRecurringDepositRepository`.
  - Updated `onLogPayment` in `RDMonthlyOperationsView` to use `await repository.getRDInstallments(item.deposit.id)` instead of an auto-dispose StreamProvider future.
  - Added graceful empty/error feedback via floating `SnackBar` if the schedule cannot be loaded.
- **Verification**:
  - Added unit test in `test/rd_monthly_operations_test.dart` verifying `getRDInstallments` returns the full 60-month schedule directly.
  - Added widget test verifying `RDLogPaymentSheet` mounts and renders properly with pre-filled `initialAmount` without throwing exceptions.
  - `dart analyze --fatal-infos`: 0 issues found!

## Surfacing Default Fee Pending Accounts & Operational Partitioning
- **User Request**:
  - What happens to accounts whose primary installment is settled but default fee is pending, in monthly view? Which filter do they show up in? Does the tile indicate it?
  - User requested: "Do it."
- **Domain State Matrix & Operational Partitioning**:
  1. `Customer Pending` (`!isInstallmentPaid && !isPoPaid`): Normal pending installment.
  2. `PO Advanced` (`!isInstallmentPaid && isPoPaid`): Paid to PO from pocket; customer collection pending.
  3. `Ready for PO` (`isInstallmentPaid && !isPoPaid`): Customer paid; deposit to PO.
  4. `Fee Pending` (`isInstallmentPaid && isPoPaid && !installment.isLateFeeResolved`): Principal & PO paid, default fee pending.
  5. `Settled` (`isInstallmentPaid && isPoPaid && installment.isLateFeeResolved`): Reconciled in full.
  - Symmetrical Partitioning:
    - **`To Collect`** captures States 1, 2, and 4 (including accounts with pending default fees).
    - **`Ready for PO`** captures State 3.
    - **`Settled`** captures State 5.
    - `toCollectCount + readyForPoCount + settledCount == totalCount` (100% symmetric and exhaustive).

  - `indicatorColor`: Amber/tertiary (`theme.colorScheme.tertiary`) for Fee Pending cards instead of settled green.

  - Trailing Column:
    - Displays `Fee Due: ₹X` in bold error text beneath monthly amount.
