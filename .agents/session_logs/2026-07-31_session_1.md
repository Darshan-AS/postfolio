# Session Log - 2026-07-31 (Session 1)

## Summary
Investigated and resolved Google Sign-In web browser freezing / popup unresponsiveness, verified Supabase local emulator execution requirements, and fixed missing Supabase RLS policies and foreign key triggers for local Postgres tables.

## Key Insights
- **Google Sign-In Popup Lockup**:
  - **Root Cause**: When running Flutter Web in Chrome debug mode (`flutter run -d chrome`), Chrome attaches DevTools Remote Debugging. On Linux (X11/Wayland), child popup windows (opened via `signInWithPopup` or OAuth window opening) fail to gain input focus, and Flutter Web's CanvasKit renderer holds a pointer capture lock (`setPointerCapture`) on the parent canvas.
  - **Workarounds & Fixes**:
    1. Use full-page redirect flow (`signInWithRedirect` or OAuth redirect) instead of popups.
    2. Run without debugging (`Ctrl + F5` or `flutter run -d web-server --web-port=3000 --dart-define=USE_EMULATOR=true`) in standard Chrome.
    3. Use `Alt + Tab` or click parent canvas to release Linux window manager input grab.

- **Supabase Local RLS, Schema & Foreign Key Fixes**:
  - **Root Cause**:
    1. The SQL migration (`20260626000000_initial_schema.sql`) defined column `account_number` on `recurring_deposits` and `one_time_deposits`, but the Freezed Dart models serialize `accountNo` to `account_no`. PostgREST rejected inserts with `Could not find the account_no column in recurring_deposits`.
    2. `recurring_deposits` and `one_time_deposits` were missing the `customer_id` column present in the Freezed model JSON payloads.
    3. Missing explicit table-level `GRANT` permissions for `authenticated` and `anon` roles.
  - **Fixes Applied**:
    1. Renamed `account_number` to `account_no` and added `customer_id` foreign keys on `recurring_deposits` and `one_time_deposits` in `supabase/migrations/20260626000000_initial_schema.sql`.
    2. Added nominee persistence to `SupabaseRecurringDepositRepository` and `SupabaseOneTimeDepositRepository`.
    3. Re-applied database migrations cleanly with `npx supabase db reset`.
