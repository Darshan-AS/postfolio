# Session Log: 2026-10-08 (Session 1)

## Goal
Implement Step 1 of the Supabase performance stabilization: optimize customer list streaming to eliminate the 749-row lateral join loop on CDC events, while preserving real-time synchronization and lazy-loading customer detail views.

## Implementation Details
1. **Lightweight Customer List Stream**:
   - In `lib/features/customers/data/supabase_customer_repository.dart`, refactored `watchCustomers()` to directly map Supabase stream rows from the base `customers` table filtered by `agent_id`.
   - Removed `.asyncMap((_) async { ... select from customer_details_view ... })`, completely eliminating the lateral join (`sa_lat`) and `get_account_nominees` executions across all 749 rows on every CDC change event.
2. **Single Entity Async Builder**:
   - Added `AsyncSingleEntityBuilder<T>` to `lib/core/widgets/feedback/async_entity_builder.dart` for individual `AsyncValue<T>` state handling.
3. **Lazy Single-Customer Detail & Edit Loading**:
   - In `lib/features/customers/presentation/screens/customer_detail_screen.dart`, updated customer detail loading to watch `customerByIdProvider(customerId)` via `AsyncSingleEntityBuilder<Customer>`, fetching the full `customer_details_view` with savings account and nominees strictly for the active customer ID on demand.
   - In `lib/features/customers/presentation/screens/customer_form_screen.dart`, updated edit mode (`customerId != null`) to watch `customerByIdProvider(customerId!)` and creation mode (`customerId == null`) to render immediately without watching list providers.
4. **Tests & Validation**:
   - Updated `test/supabase_customer_repository_test.dart` to assert customer base fields on `watchCustomers()` and full savings account details on `watchCustomerById()`.
   - Added `CustomerCard` and `AsyncSingleEntityBuilder` widget tests in `test/widget_test.dart`.

5. **Phase 1: Deposit List & Detail N+1 Optimization**:
   - In `OneTimeDepositCard` and `RecurringDepositCard`, updated title resolution to read pre-joined `deposit.customerName` directly, eliminating hundreds of spawned stream subscriptions to `customerByIdProvider` across the deposit list views.
   - In `OneTimeDepositDetailScreen` and `RecurringDepositDetailScreen`, preferred `deposit.customerName` over redundant `ref.watch(customerByIdProvider)`.
   - In `OneTimeDepositFormScreen` and `RecurringDepositFormScreen`, bypassed list controller stream watchers when creating new deposits (`depositId == null`).
   - Added widget tests verifying deposit cards render `customerName` directly and form screens render on create.

6. **Phase 2: Single-Deposit Detail Providers & Watchers**:
   - Added `watchOneTimeDepositById` and `watchRecurringDepositById` to repository interfaces and implementations across Supabase, Firestore, and Fake repositories.
   - In Supabase repositories, single-deposit streams listen to `account_identities` filtered by `id` and query `one_time_deposit_details_view` / `recurring_deposit_details_view` directly.
   - Added `@riverpod` family providers `oneTimeDepositById` and `recurringDepositById` in controllers.
   - Refactored `OneTimeDepositDetailScreen` and `RecurringDepositDetailScreen` to use `AsyncSingleEntityBuilder`, isolating detail screen updates and removing whole-list controller dependencies.
   - Refactored deposit form screens edit mode (`depositId != null`) to use `AsyncSingleEntityBuilder` watching single deposit providers.
   - Hardened `toggleDepositStatus` to accept direct deposit instances with fallback to single-entity queries.
   - Added widget tests for single deposit detail screens with provider overrides.
