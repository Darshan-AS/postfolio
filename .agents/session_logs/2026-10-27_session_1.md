## Key Findings (full detail in artifact `rd_ledger_branch_critique.md`)
1. **Blocker (confirmed at runtime)**: `upsert_and_prune_rd_installments` references the INSERT FROM-alias `elem` inside `ON CONFLICT … DO UPDATE` → `column "elem" does not exist` on the very first call. All Supabase ledger writes (payment, edit, delete, waiver) are broken; tests are green only because they use the Fake repo. No RPC integration tests exist.
2. **Financial math**: payment on the due date is charged a 1% fee (midnight `dueDate` vs wall-clock `now`); default fee freezes at first assessment and never accrues; live allocation (`allowPoolOverflow=false`) ≠ replay allocation (`true`) so edits retroactively reallocate confirmed payments; leftover amounts silently dropped; custom split not reconciled; floating-point money.
3. **Data integrity**: PostgREST `max-rows` truncation of the global sparse stream feeds *writes* via `prepareLogPayment`; no optimistic concurrency (lost-update race); `record_rd_po_payments` INSERT path lacks `assert_account_owner`; `rd_payment_allocations` is write-only and goes stale; `save_recurring_deposit` purges sparse rows on unrelated edits; legacy `installment_no = NULL` rows.
4. **State mgmt/perf**: zero `.select()` — whole hub re-hydrates on every keystroke/checkbox; `AsyncValue(:final value?)` hides errors/loading; no busy state on submit buttons (double-tap = duplicate transaction); `Failure` results dropped at 6 call sites.
5. **Conventions**: domain service called from widgets; `useState` inside `.when(data:)`; status state-machine duplicated 3× with divergent colours; 13 widget `DateTime.now()` sites; 6 non-adaptive bottom sheets; magic numbers; raw enum strings in queries.
6. **UX**: batch bar renders `"3 selected ()"`; `selectAll` replaces selection; "Advance" has 3 opposite meanings; single-row Deposit has no confirm/undo; split selector exposed on every payment; heatmap cells ~21×24 dp with 8.5 pt text and no `Semantics`; two identical CTAs on first paint of RD detail.
7. **Hygiene**: 27 unused i18n keys, dead month-query API + dead SQL view, 500-line Fake repo in production file.

## Redesign Proposal (follow-up question)
- Artifact: `rd_ledger_redesign_proposal.md`. Recommendation: redesign the ledger **core**, keep the UI shell.
- Root cause: `rd_installments` persists *derived* state written absolutely from client snapshots. Proposed: facts-only schema (`rd_transactions`, new `rd_po_deposits`, new `rd_fee_waivers`), one pure `RDLedgerProjector` (replaces live/replay split, hydrate/diff/prune, allocations table), per-RD bounded fact streams for writes, optional `rd_ledger_summary` cache (1 row/RD) for the Hub, calendar-day money semantics, split hub notifiers, single status mapper.
- Matrix: 30 of 42 critique issues eliminated by construction, 8 mitigated, 4 untouched (UI polish/a11y/terminology).
- Rationale for doing it now: Firestore→Supabase migration not yet run in prod, so schema change is cheapest today; net LOC decreases. Aligns with roadmap item RDL-10.
