## Findings — official `material_ui`
Sources: pub.dev API and changelog page, and the 1.11.0 archive unpacked and searched.
- Latest is 1.11.0, published 2026-11-09. Twelve releases since 1.0.0 (2026-08-12), about one a week. Needs Flutter >= 3.47.0 from 1.4.0 on, so it works with the local SDK.
- `flutter pub upgrade --dry-run material_ui` resolves to 1.11.0 and changes that one dependency.
- Material 3 Expressive in the changelog:
  - 1.2.0: `StyleVariant` enum (`material3`, `material3Expressive`).
  - 1.5.0: Expressive `IconButton`.
  - 1.8.0: `RoundedPolygon`, `CornerRounding`, `MaterialShapes`, `MaterialShapeBorder` (morphs when lerped).
  - 1.11.0: Expressive `ElevatedButton` with selectable states, `Springs` motion tokens, `IconButtonTheme.variantOf`, `ElevatedButtonTheme.variantOf`.
- In the 1.11.0 source, `StyleVariant` is referenced by six files: `button_style`, `elevated_button`, `elevated_button_theme`, `icon_button`, `icon_button_theme`, `theme_data`. The variant is set per component theme; `ThemeData` has no app-wide switch.
- The enum's own doc says Expressive support "is under development" and that opting in "may see visual changes as more Expressive features get added".
- A search of the source for classes named after the other Expressive components (loading indicator, button group, split button, FAB menu, floating toolbar, wavy progress) found none. This was a search by class name, so a component under an unexpected name would have been missed; the changelog agrees with it.
- Umbrella issue flutter/flutter#168813 ("Bring Material 3 Expressive to Flutter") is open, P3, last updated 2026-08-17.

Checked in the `material_3_expressive` 1.2.1 source:
- `flutter pub add material_3_expressive --dry-run` resolves against this project: adds `material_3_expressive 1.2.1`, `motor 1.1.0`, `material_new_shapes 1.0.0` and moves `material_ui` to 1.11.0. Nothing else changes.
- `M3ETheme.of(context)` falls back to `M3EThemeData.fromMaterial(Theme.of(context))` (`lib/foundations/theme/m3e_theme.dart:70`), and all 296 theme lookups in its components go through `M3ETheme.of`. So its widgets take colours from the app's existing `ThemeData` without `M3EMaterialApp`. The README says the fallback is "a default light theme"; the source disagrees.
- 590 Dart files, about 162k lines, of which about 52k are one icon-constants file. 88 test files, 685 `test`/`testWidgets` calls.
- Seven public fields are typed `IconData` (toolbar action, split-button leading icon, text-field affordance, sheet and picker headers); 56 icon slots take a `Widget`. `HugeIcon` fits the `Widget` slots only. Toolbars also accept `M3EToolbarWidget(child:)`.
- It re-exports `RoundedPolygon` and `CornerRounding` from `material_new_shapes`, which clash with the `material_ui` 1.8.0+ names; one side must be hidden on import.
- Its text field is not a `FormField`.

Not checked: whether its widgets pass this repo's layout and accessibility suite (`test/ui/accessibility_and_layout_invariants_test.dart`: 44dp targets, tooltips, 2.0x text scale), how they render under `Skeletonizer`, and any device or web build. Nothing was compiled against either candidate.

## M2 — Theme
- New token files in `lib/core/theme/`:
  - `app_shapes.dart`: the Expressive corner scale (4 … 48, including the three steps Expressive added) and the grouped-row radii (20 outer, 4 inner, 2 gap).
  - `app_motion.dart`: the official `Springs` tokens, plus `SpringCurve` so implicit animations and `flutter_animate` can follow a spring. `AppAnimations` now reads its durations and curves from it.
  - `app_typography.dart`: tabular figures on every role (as before) and the emphasized roles (`AppTypography.emphasizedOf(context)`).
  - `app_surfaces.dart`: `ColorScheme.page` (`surfaceContainer`), `.raised` (`surfaceBright`), `.inset` (`surfaceContainerHigh`). Content is separated by tone, not outlines.
- `AppWidgetThemes` rewritten on those tokens. `IconButton` and `ElevatedButton` opt into the official `StyleVariant.material3Expressive`. The other official buttons get a pill that squares off while pressed. New themes for dialogs, bottom sheets, menus, date picker and banner.
- App bar height is now 64 (`AppDimensions.appBarHeight`), the Material 3 small top app bar.
- **Brand palette**: `ColorScheme.fromSeed` now uses `DynamicSchemeVariant.vibrant` for the brand seed. The default variant turned `#1A56DB` into a slate blue; `vibrant` keeps the primary close to the seed with pastel containers. This only shows where the device gives no dynamic colours (web, desktop, iOS, Android 11 and older) and in the accessible themes.
- **Defect found in the screenshots and fixed**: `ThemeData.textTheme` carries colours and the font family but no sizes (sizes are merged in per locale by `Theme.of`). Component themes replace a widget's default style, so the first version rendered the app bar title at 14sp. Component styles are now built from the text theme merged with `typography.englishLike`. English is the only supported locale.
- **Verified** with no screen code changed: analyzer clean; 213 fast tests pass, including the 360×800 @ 2.0x overflow and tap-target matrix.

Seen failing with a probe file placed in `lib/core/`, then passing once it was removed.
- What the screenshots and a throw-away test showed, and what was done:
  - `M3EButtonGroup` keeps an invisible copy of every label in the tree to measure it, so `find.text('Monthly hub')` matched two widgets. `AppButtonGroup` is built from the package's toggle buttons in a `Row` instead. Measured after the change: each label found once; the group's box is 48dp tall; a tap 1dp inside its top edge, above the 40dp pill, selects the segment.
  - Segment labels do not wrap. Above 1.3x text the segments stack vertically.
  - `M3ELoadingIndicator` asserts a size of at least 24; the wrapper raises smaller values.
  - The navigation wrappers cap label scaling at 1.3x, as the official `NavigationBar` does.
  - A long label in a full-width `AppButton` at 2.0x text ellipsizes; no overflow.
- Not used: `M3EMaterialApp`, `M3ETheme`. The community widgets read `Theme.of(context)`.
- **Verified**: analyzer clean; 213 fast tests plus the new boundary test pass.
- **Unintended run**: one command passed `--exclude-tags` twice; the second replaced the first, so the 15 integration tests ran against the local Supabase stack. "Hub: summaries stream, backfill, rows, KPIs" failed once in that run (`hasSummary` false after its 500 ms wait) and passed when its file was run again on its own. It exercises providers and Realtime, not UI. Later runs use `--exclude-tags "integration || visual"`.

### Defects found on the way and fixed
- **Extended FAB overflow** — caught by the existing 360×800 @ 2.0x matrix, which failed for Customers and One-time deposits in light and dark (`RenderFlex overflowed by 90 / 58 pixels`). The community FAB lays out its label in a row that does not shrink. `AppExtendedFab` now caps the label at 1.3x text and scales the button down if it is still wider than the window less its margins. With the real Roboto font the same screen did not overflow; the test's fixed-width font did, so a longer label or translation would have.
- **Wrong icon colour on a filled button in an app bar** — seen in a screenshot: the form's confirm tick was `onSurfaceVariant` on `primary`. `IconButton.themeStyleOf` takes the ambient `IconTheme` colour as the button's foreground, ahead of the variant's default, and `AppBar` wraps its actions in an `IconTheme`. `FormAppBar` and `EntityDetailScaffold` set the foreground on those two buttons.

- **Rail labels clipped** — seen in a desktop screenshot of the shell through the real router: "Dashboar", "Customer". The community rail pads its 96dp width by 20dp a side and does not ellipsize. `AppNavigationRail` overrides that padding to 8dp through a local `M3ETheme`; the labels now show in full.
