Implement a glanceable, uncomplicated checkpoint strip in `RDMonthlyOperationCard` to clearly communicate the three operational dimensions of an RD installment:
1. Customer payment of base installment
2. Post Office (PO) deposit status
3. Default fee status (shown only when needed: pending, paid, or waived; completely hidden if no default fee exists).

## Problem & Design Rationale
- **The Glanceability Friction**:
  - The leading avatar previously displayed `#N` (e.g. `#9`), which provided passive historical tenure rather than active operational status. For ~85% of cards in an active month, all avatars looked identical.
  - Furthermore, status badges in the card subtitle were scattered and wrapped unpredictably across multiple lines.
- **User Chosen Approach (Option A with Conditional Fee)**:
  - Keep `#N` in the circle avatar (transitioning to checkmark when settled).
  - Add a dedicated, structured Checkpoints Bar in the subtitle:
    - **Checkpoint 1 (Customer)**:
      - `[ ✓ Cust Paid ]`: Primary container, checkmark icon.
      - `[ ! Cust Overdue ]`: Error container, alert icon.
      - `[ 🪙 Cust: ₹X ]`: Primary container, coins icon for partial collections.
      - `[ ⏳ Cust Pending ]`: Surface container highest, clock icon.
    - **Checkpoint 2 (Post Office)**:
      - `[ ⚡ Advanced to PO ]`: Tertiary container, flash icon (paid from agent's pocket before collection).
      - `[ ✓ PO Deposited ]`: Primary/secondary container, checkmark icon.
      - `[ ⏳ PO Pending ]`: Surface container highest, clock icon.
    - **Checkpoint 3 (Default Fee - Conditional)**:
      - Hidden completely when no default fee exists (on-time payments with 0 fee).
      - `[ ⚠️ Fee: ₹X ]`: Error container, alert icon when fee is owed.
      - `[ ✓ Fee Paid ]`: Primary container, checkmark icon when customer paid late fee.
      - `[ Fee Waived ]`: Surface container highest, check badge icon when forgiven.

## Follow-up: "Collect Fee" Button Defaulting to Installment Collection Fix
- **Problem**: 
  - Tapping "Collect Fee (₹X)" on a fee-pending card (`item.isFeePending == true`) opened `RDLogPaymentSheet` with the fee amount (e.g. ₹20).
  - However, because ₹20 was less than the monthly installment (`20 < 1000`), `RDLogPaymentSheet` defaulted its split mode to `PaymentSplitMode.installmentsOnly`.
  - This mistakenly prefilled the payment as an advance installment credit rather than applying it to settle the pending penalty.
- **Solution**:
  1. **`RDLogPaymentSheet` (`rd_payment_bottom_sheets.dart`)**:
     - Added optional `PaymentSplitMode? initialSplitMode` parameter.
     - Enhanced default split mode resolution: if all past principal installments are settled and only default fees remain (`pendingPrincipalTotal == 0.0 && pendingLateFeesTotal > 0`), it automatically defaults to `PaymentSplitMode.feesOnly`.
  2. **`RDMonthlyOperationsView` (`rd_monthly_operations_view.dart`)**:
     - In `onLogPayment`: when `item.isFeePending` is true, passes `amount: item.totalDefaultFee(now)` and `initialSplitMode: PaymentSplitMode.feesOnly`.
     - When overdue with fees: passes `initialSplitMode: PaymentSplitMode.includeFees`.
- **Verification**:

## Option 1: The "Filled vs. Hollow" Visual Hierarchy
- **Rationale**: 
  - Having text-only distinctions between "Cust Paid" and "Cust Pending" or "PO Deposited" and "PO Pending" required users to read text to understand status.
  - Option 1 establishes an instant shape-and-fill distinction:
    - **Solid Filled Pills**: Represent completed or actionable positive actions (`[ ✓ Cash ]`, `[ ✓ PO ]`, `[ ⚡ PO Adv ]`, `[ ! Cash ]`).
    - **Hollow / Outlined Ghost Pills**: Represent pending or waiting states (`[ ○ Cash ]`, `[ ○ PO ]`).
    - **Entity Invariance**: The text label is constant (`Cash` and `PO`), so the user never has to read different words.
    - **Conditional Default Fee**: Displayed only when relevant (`[ ⚠️ Fee: ₹X ]`, `[ ✓ Fee ]`, `[ Fee Waived ]`, hidden if 0/none).
- **Implementation**:
  - Updated `_buildCheckpointBadge` with `bool isOutlined = false` and `Color? borderColor`.
  - Updated `_buildCustomerCheckpoint`, `_buildPoCheckpoint`, and `_buildFeeCheckpoint` to leverage the new Slang keys and outlined styling.
  - Updated widget tests in `test/rd_monthly_operations_test.dart` to assert badge fill vs. outline decorations.

## Refinement: Fraction / Split Format for Both Cash & Fee
- **Rationale**:
  - User requested refinement on partial cash and default fee consistency.
  - Aligned partial cash and partial fee with the core rule: **Solid = Complete, Hollow = Incomplete/Pending**.
  - User requested: "Show fraction / split for both".
  - Solves the mental flip where previously cash showed already paid and fee showed remaining.
  - By using fraction split `${paid}/${total}` for partial payments, the pill simultaneously shows **what has been collected** (numerator) and **what the total target is** (denominator).
- **Rules & Visual Mapping**:
  1. **Partial Cash (On-Time)**:
     - `[ 🪙 Cash: ₹X ]`: Outlined in primary (`borderColor: primary`, `fgColor: primary`, `isOutlined: true`).
     - Rationale: Transparent/hollow signifies incomplete (balance pending); primary color + coins icon celebrates cash received.
     - `[ 🪙 Cash: ₹400/₹1,000 ]`: Outlined in primary (`borderColor: primary`, `fgColor: primary`, `isOutlined: true`).
     - Shows `inst.customerPaidAmount` / `inst.installmentAmount`.
  2. **Partial Cash (Overdue)**:
     - `[ 🪙 Cash: ₹X ]`: Outlined in error (`borderColor: error`, `fgColor: error`, `isOutlined: true`).
     - Rationale: Transparent/hollow signifies incomplete; error color alerts that the remaining balance is past due.
     - `[ 🪙 Cash: ₹400/₹1,000 ]`: Outlined in error (`borderColor: error`, `fgColor: error`, `isOutlined: true`).
     - Shows `inst.customerPaidAmount` / `inst.installmentAmount`.
  3. **Full Overdue Cash (0 Paid)**:
     - `[ ! Cash ]`: Solid error container (`bgColor: errorContainer`, `fgColor: error`). Urgent collection alert.
  4. **Partial Default Fee (Paid part, penalty remaining)**:
     - `[ ⚠️ Fee: ₹X ]`: Outlined in error (`borderColor: error`, `fgColor: error`, `isOutlined: true`).
     - Displays net remaining fee due. Outlined signifies incomplete/partially addressed.
     - `[ ! Cash ]`: Solid error container.
  4. **Partial Default Fee**:
     - `[ ⚠️ Fee: ₹10/₹20 ]`: Outlined in error (`borderColor: error`, `fgColor: error`, `isOutlined: true`).
     - Shows `inst.paidLateFee` / `totalAssessedFee`.
  5. **Full Unpaid Default Fee (0 Paid)**:
     - `[ ⚠️ Fee: ₹X ]`: Solid error container (`bgColor: errorContainer`, `fgColor: error`). Urgent penalty alert.
     - `[ ⚠️ Fee: ₹20 ]`: Solid error container.
     - `[ ⚠️ Fee: ₹0/₹20 ]`: Outlined in error (`borderColor: error`, `fgColor: error`, `isOutlined: true`).
  6. **Settled States (100% Complete)**:
     - `[ ✓ Cash ]`, `[ ✓ PO ]`, `[ ✓ Fee ]`: All solid primary containers.
     - `[ ✓ Cash ]`, `[ ✓ PO ]`, `[ ✓ Fee ]`: Solid primary containers.
     - `[ ✓ Cash: ₹1,000/₹1,000 ]`, `[ ✓ PO ]`, `[ ✓ Fee: ₹20/₹20 ]`: Solid primary containers.
