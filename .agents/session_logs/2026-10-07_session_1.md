# Session Log: 2026-10-07 (Session 1)

## Goal
Debug production Supabase migration and auth issues reported on distributed release `v2.0.0+17`, verify build readiness of `main` branch for next release, and resolve web crash when running Chrome presets.

## Findings & Root Cause Analysis
1. **Data Migration Status**:
   - Confirmed all 749 customer records exist in production Supabase; initial appearance of fewer records was due to default pagination in the Supabase Table Editor.
   - APK and data were confirmed pointing to live production Supabase, not local dev emulators.
2. **Lag & Auth Revocation Root Cause**:
   - Released APK `v2.0.0+17` (commit `77e73e8`) had unfiltered real-time CDC streams in `SupabaseCustomerRepository`, `SupabaseOneTimeDepositRepository`, and `SupabaseRecurringDepositRepository`.
   - Any mutation triggered cascading full view queries (`customer_details_view` with lateral joins and `get_account_nominees` across 749 rows) on all active devices.
   - Sustained request floods from the Wi-Fi network triggered Cloudflare / Supabase WAF automated rate limiting (dropping TLS handshakes via `TCP RST`), causing `AuthRetryableFetchException with HandshakeException: connection terminated during handshake`.
   - Cellular data assigns a clean carrier IP, bypassing the WAF IP rate limit and allowing login to succeed.
3. **`main` Branch Readiness**:
   - Commits `d3df19e` (filter CDC streams by agent ID) and `0bede68` (server-side customer name joins in views) directly eliminate the runaway query loop and client mapping overhead.
   - Validated static analysis (`flutter analyze` passes with 0 issues).
   - Validated Web target compilation (`flutter build web` passes with exit code 0).
   - Validated Android assemble task (`flutter build apk --flavor prod --debug` passes with exit code 0).
4. **Chrome Web Crash Resolution**:
   - In `lib/main.dart`, `FirebaseCrashlytics.instance` was called unconditionally. FlutterFire Crashlytics is unsupported on Flutter Web and threw `UnsupportedError: Crashlytics is not supported on web`, crashing Chrome on startup.
   - Guarded Crashlytics initialization with `if (!kIsWeb)`.
   - Identified that the local `.vscode/launch.json` "Chrome - Production" preset relies on `Env.supabaseUrl`, which is compiled from `.env`. When `.env` is pointing to `http://127.0.0.1:54321`, `.env.prod` must be copied to `.env` and compiled via `build_runner` to target the live database.
