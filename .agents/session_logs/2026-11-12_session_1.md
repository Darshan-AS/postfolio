### A2 — PO visit write path
- **Red** (fake with a 30 ms write round trip and Riverpod provider retry off):
  - saved visit returned `Failure` when reads failed after the insert;
  - a retry after a lost response stored a second event for the same account (months 3–4);
  - 12 fact streams were opened for a 2-account visit;
  - undo did not mark accounts dirty when its refresh could not read.
- **Correction to the audit**: with zero latency the post-insert re-read hit still-cached providers and did not fail, and with retry on, Riverpod retries a failed provider for roughly 30+ s before `.future` rejects (the undo test ran past the 30 s test timeout before returning `Failure`). So a brief blip is retried rather than failing the visit; the failure needs reads to stay down past that window, during which the global busy flag is held. The audit's "any one failed request triggers it" overstated this.
- **Fix**: see `progress.md` A2. Fake gained `failReadsWith`, `failAddPoDepositsAfterCommitOnce`, `onPoDepositsAdded`, `writeLatency`, `streamOpenCount`.
- **Verified**: analyzer clean; 167 fast tests pass; `supabase_rd_ledger_e2e_test.dart` passes against local Supabase (10 tests), including a 250-id chunked facts read and a re-sent visit stored once then undone.
