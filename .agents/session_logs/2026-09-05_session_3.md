# Session Log: 2026-09-05 (Session 3)

## Goal
Implement functionality to edit and delete RD customer payment transactions, automatically recompute installment allocations, and provide mechanisms to revert or update Post Office (PO) installment settlement statuses when marked in error, all adhering to strict Domain-Driven Design (DDD) and "Brain & Muscle" separation.

## Architectural Design & DDD Compliance
1. **Domain Layer (The Brain)**:
   - Implemented `RDLedgerService.recomputeScheduleFromTransactions(...)` in `lib/features/recurring_deposits/domain/rd_ledger_service.dart`.
   - Pure, deterministic calculation: resets customer payment fields across the schedule (respecting opening baseline `initialPaidInstallments` and preserving PO settlement fields `poStatus` and `poPaidDate`), sorts surviving transactions chronologically, and replays each through `allocateCustomerPayment`.
2. **Infrastructure Layer (The Muscle)**:
   - Created PostgreSQL migration `supabase/migrations/20260905000000_rd_transaction_mutations.sql` introducing atomic RPCs `delete_rd_transaction` and `update_rd_transaction`.
   - Enforced row-level security and ownership assertions (`assert_account_owner`).
   - Repositories (`RecurringDepositRepository`, `SupabaseRecurringDepositRepository`, `FakeRecurringDepositRepository`) updated with `deleteCustomerPayment` and `updateCustomerPayment`.
3. **Application Layer (Use Case Orchestration)**:
   - Added `deleteCustomerPayment`, `updateCustomerPayment`, and `revertPoPayments` in `RDLedgerController` to orchestrate recomputation through `RDLedgerService` and pass results to repositories.
4. **Presentation Layer (Dumb Widgets)**:
   - In `RecurringDepositDetailScreen`:
     - Added `MenuAnchor` actions on transaction list tiles: "Edit Payment" (opens `_EditPaymentBottomSheet` with live reactive allocation preview) and "Delete Payment" (with confirmation dialog).
     - Extended PO selection mode ("Manage PO") to allow selecting both paid and unpaid installments, dynamically offering `Deposit (N)` and `Revert (N)` (with confirmation) actions.
